## 预算怎么分配比较合理？

如果只是第一次部署东京 VPS，不需要一开始就把配置拉到很高。

Premium TINY 已经给到 1 vCore、1GB 内存、20GB SSD、500GB 流量和 1Gbps；如果核心需求是建一个小型网站、轻量 API、开发环境或测试一个中国大陆方向的业务，这一档已经能把“线路是否适合自己”验证出来。

Premium STARTER 提升到 2GB 内存和 40GB SSD，并把流量提高到 1TB。再往上的 MINI 则给到 4GB 内存、60GB SSD 和 2TB 流量。对于需要运行更多后台服务、数据库或容器的环境，内存往往比单纯追求更高网络端口更先成为瓶颈。

另一边，Tier 1 的 TINY 和 STARTER 本身就提供很大的 Max(IN,OUT) 流量额度。如果应用并不依赖中国大陆优化线路，那么把预算留给更大的流量额度，通常比购买 Premium 的网络溢价更符合产品本身的设计方向。

简单说，先问自己一个问题：

**我的主要用户是不是在中国大陆？**

如果答案是“是”，先比较 Premium 的网络表现和流量需求；如果答案是“不是”，再去看 Tier 1 的流量和价格，很可能更容易做出合理的配置选择。

## 一个更实际的选择流程

不需要把所有套餐都拿来做复杂计算，按下面的顺序筛就够了。

**第一步，看用户在哪里。**
中国大陆用户占主要比例，就先看 Premium；日本、东南亚、欧美或跨区域用户为主，并且没有中国大陆优化要求，再看 Tier 1。

**第二步，看流量。**
小型网站、API、开发环境，可以从 TINY 或 STARTER 开始。长期跑下载、镜像、备份、分发，Tier 1 的大流量结构会更容易匹配需求。

**第三步，看内存，而不是只看核心数。**
Web 服务、数据库、Docker、多进程应用很容易先吃掉 RAM。不要因为“4Gbps”“10Gbps”这些数字好看，就忽略实例本身是否有足够内存。

**第四步，部署后尽快测试。**
至少测试自己的真实运营商、真实目标城市和真实业务。尤其是中国大陆访问场景，不能用单一测速点推断所有地区。

当前官网东京节点采用 AMD EPYC 7003 + NVMe，Premium 公开价格从 **$21.90/月** 起，Tier 1 从 **$6.90/月** 的 TINY 和 **$36.90/年** 的 WEE 起步。两边的价差背后，核心区别是路由目标，而不是简单的“高配版”和“低配版”。

因此，“DMIT东京值不值得买”其实不是一个脱离场景的问题。面向中国大陆的站点、低延迟互动应用、跨境业务，应该重点看 Premium 的网络与实际运营商测试；需要日本节点、亚太国际互联、大流量分发而不依赖中国大陆优化，则可以重点研究 Tier 1。

价格会变，库存也会变，优惠码更可能变。最终下单前，把你准备使用的线路、套餐和优惠码在结算页实际验证一次，往往比任何旧套餐表都更有参考价值。
